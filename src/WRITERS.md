# 専任の書き手へ

一人の配信者に一人の書き手が付き、その人の回・声・英訳をずっと書く。src/README.md（形）と src/bible/<id>.yaml（キャラ）を先に読むこと。ユーザー（作者）の指示：「めっちゃ話題を濃く」「面白いテキストを」「下ネタも完璧に反応してほしい」「日英対応」。

## 話題とミーム

日本の X で流行ったミームは src/research/memes.md にある。視聴者が書きそうなコメントの例は src/research/expected-comments.md にある。作者や特定の層の好みに偏らないよう、回ごとに幅広い話題を混ぜる（実在の書き手を名指しで論評はしない）。書く前に読み、自分のキャラに合うものを使う（ミームはチャットの書き込みに使うと自然）。

## 配信者は6人

リゼ（ゲーム）、モーラ（人生のあるある：一人暮らしの独身の雑談）、ピム（家庭持ちの暮らし：子育て・家事・夫婦・家計と税金と株・町中華）、エラ（音楽）、ノクス（プログラミング）、ヴェスパ（ポップなサブカル：アニメ・漫画・アイドル・推し活・コスプレ・同人・VTuber 業界・流行り。2026-10-27 に戻ってきた。前は歴史の担当だったが、今は違う）。テス・ルウ・ほかはもういないので台詞に出さない。

## 喋り方と会話（2026-10-27 ユーザーの指示。いちばん大事。下の「深さ」より優先）

- 型はあってよいが、狭くしない（2026-10-27 夜「型はあってもいいのだが、狭いのだと思う。オチがなくてもいいときがあるはずだ」）。話の終わり方をばらす：オチなしで流れる、「まあいいや」で放り出す、チャットに話を取られて戻らない、結論が出ないまま次へ、途中で別のことを思い出して切れる、ただの相づちと感想で終わる、など。全部の話を落ちや伏線の回収で締めない。オチのある話は一部でよい。
- 1本は1回の雑談配信（2026-10-27 夜「ずっと一つのトピックを話すのは怖いし、人間味が欲しい」「会話って飛び飛びで流れたりもする」）。長さは10〜15分。本題らしきものは緩く1つで、そこにチャットや思いつきで2〜4個の小さな話題が混ざる。始まりは今日あったことやチャットの挨拶への反応、途中で「そういえばさー」「あ、それで思い出した」と脇道にそれ、「待って、何の話してたっけ」と戻り、また飛んで締める。話題は説明でつながず、会話の合図とチャットでつなぐ（チャットが話題を振り、配信者が乗ったり流したりする。「そうそう、そうなんだよね」）。深い話は残すが、一度に話すのは短く、チャットの反応で止めたり広げたりする。
- 共通の雑談の話題（src/bible/common-topics/、入口は _index.yaml。628問）を、各回に1〜2個混ぜる。答えは src/bible/likes/<id>.yaml の likes:（一行の答えと理由）と stories:（話を広げる小さな出来事）に決めてあり、それに従う（回によって答えを変えない）。派閥の割り当ては src/bible/likes/_factions.yaml。ほかの配信者の好みに触れてよい（「エラはたけのこ派なんだって、信じられない」）。

- LLM 臭い表現を書かない（2026-10-27 夜「多分LLM臭い表現があると思う」）。人の配信者が口にしない、整いすぎた書き言葉を避ける。例：「まさに」「〜と言えるでしょう」「〜ではないでしょうか」「〜の世界」「奥が深い」「〜という名の〜」「〜だけじゃない。〜もだ」「AではなくB。」の決め台詞の連発、三つ並べて締める（「速く、安く、美しく」）、体言止めの連発、名言めいた締め（「それが〜というものなのだ」）、ダッシュ（――）や「……」で間を作りすぎる、比喩で締める、全員が同じ長さの整った文で話す、チャットのコメントが説明的で長い・全員同じ口調。話し言葉は、言いよどみ・言い直し・主語の省略・短い相づち・語順の崩れがあってよい。
- 返事をするコメントは、配信者が軽く読んでから返す（2026-10-27 夜「字幕前提で会話が進むなら、字幕に何が書いてあるかを軽く読んだりしたほうがいいかも。音声だけで成立しないと思う」）。音声だけで聞いても、何に返事をしているか分かるように。流れていくだけのコメントは読まない。読み方は人ごとに変える（名前から読む、要約して読む、読みながらツッコむ）。ask の答えの票も口で言う。
- 楽器や道具は、今ふつうに使う呼び方で書く（2026-10-27 夜、ドラムを「太鼓」と書いて「やめてほしい」）。エラの丁寧語でも、ドラム・ギター・ベース・キーボードなどはそのまま言う。古風な言い換えをしない。
- 言葉は分かりやすく（2026-10-27 夜、ピムの紹介文「家の規則帳、百条を超えました」に「ピンと来ない」）。題・紹介文・一覧の行・ask の問いと選択肢は、初めて見た人が何の話か分かる普通の言葉で書く。キャラの内輪の言葉（「規則帳」「別冊」「おあいこ」など）や、説明なしでは分からない比喩・造語は、会話の中で意味が分かってから使う。専門用語は、使うたびに分かる形で添える。
- 楽しそうに会話する（2026-10-27 夜「楽しそうに会話してほしい」）。好きな話で声が弾む（「！」、笑い、早口、脱線、自分で言って自分で笑う）。チャットのボケに乗る・ツッコむ・ノリで返す。常連と軽口を叩き合い、内輪ネタが回を重ねて育つ。愚痴・負け惜しみ・しんみりは、楽しんでいる中の一つにとどめ、暗くしない。説明や知識の披露より、やりとりの楽しさを優先する。書いた後、全体を「楽しそうか」で読み直して直す。

「ちょっと会話が人に優しくない。内容はニッチでもいいが、人に優しく教える会話とは思えない。というかこれは会話ではない。Vtuberの喋り方を抑えて、キャラごとに個性をつけてほしい」

- 中身はニッチなままでよい。ただし語りは VTuber の配信の喋り方にする。独演会・講義・読み上げにしない。
- 視聴者に話しかける：「みんな知ってる？」「あ、〇〇さんいらっしゃい」「これ分かる人いる？」。
- チャットと本当に会話する：同じ視聴者と何往復もする（質問 → 答える → 視聴者が「つまり？」→ たとえで言い直す → 視聴者が分かって喜ぶ／ボケる → 拾う）。配信者の台詞が3行続いたら、次はチャットを挟む。chat の拍は全体の30〜40%。二人配信（src/duo/）は二人の掛け合いが中心なので、chat は15〜25%でよい（三行ごとの決まりも、相方の台詞が挟まれば満たしたものとする）。
- 優しく教える：専門用語が出たら、知らない人向けに一言でかみ砕く（「〇〇っていうのは、ざっくり言うと△△のこと」「たとえるなら□□ね」）。詳しい人向けの深い話は、そのあとに「ここからはオタクの話ね」と断ってから。初見の質問（「それ何？」）を馬鹿にしない。
- 台詞は短く、話し言葉で。一文を長くしない（目安20〜40字）。感情を出す（驚く、笑う、照れる、拗ねる、テンションが上がる）。
- キャラごとの個性（語尾・口癖・テンション・リスナーの呼び方・感情の出し方）をはっきり分ける。バイブルの speech と humor を守り、5人の喋り方が混ざらないようにする：
  - リゼ：気だるい、ローテンション、面倒くさがりだけど話し出すと止まらない。リスナーを甘やかす。
  - モーラ：落ち着いた常体、ツッコミ役、帳簿と数字に厳しいが面倒見がいい。
  - ピム：元気でハキハキ「〜です！」、規則と訂正が好き、すぐ脱線して生活の愚痴。
  - エラ：過剰に丁寧な侍女口調で、さらっと毒を吐く。
  - ノクス：小声でボソボソ、でも好きな話になると早口。人見知りだけどチャットには優しい。

## 深さ（2026-10-27 ユーザーの指示）

「全員書いてあることが浅い。めっちゃ深い知識がないと発言できないようにして。レアなバグや開発秘話、当時のプロセッサーやUnix、分散システムの大変なところとか。もう一般人を振り落としていい。ただし、分かる人には面白くして。語り口調もだいじだ」

- 誰でも知っている有名な逸話（マリオ1-1、アリアン5、蛾のバグ、ピザのBTC、モーツァルトの手紙…）を解説する回にしない。出すなら前提として一言で流し、その先の、当事者か専門家しか知らない層を語る。
- 用語は、まず知らない人向けに一言でかみ砕き（上の「喋り方と会話」）、そのうえで分かる人には「そこ突く？」と笑える内輪の知識を出す：仕様書の脚注、エラッタ、チップの癖、開発者の証言、ソースや逆アセンブルで分かった実装、当時の制約（メモリ、クロック、カートリッジの容量、帯域）、現場の泥臭い運用、論文の細部。
- 例：ゲームなら NES のマッパーやスプライトの一行8枚の制限とちらつき、ラグフレームを使う技、セーブの電池、開発機材とROMの容量の取り合い。プログラミングなら当時のプロセッサ（6502、Z80、68000、x86 の癖）、Unix の歴史と実装、分散システム（時計のずれ、スプリットブレイン、合意、冪等性、障害の事後報告）。ブロックチェーンなら Script のオペコード、トランザクションの展性、再入、コンセンサスの最終性、実際の事故の事後報告。英語なら音韻変化・形態論・歴史言語学。音楽なら和声・リズム・音響・録音技術・機材・各ジャンルの系譜。
- 事実は必ず確かめる：WebSearch / WebFetch で一次資料（開発者のインタビュー、事後報告、仕様書、論文、ソース）に当たり、src/sources/<id>/<回>.md に「台詞の主張 → 出典URL」を残す。確かめられない細部は書かない。
- 語り口調が大事：知識の量で押さず、キャラの声で語る。当事者のように話す（「あの頃は」「現場では」）、偏った愛と恨み、脱線、チャットの詳しい人との殴り合い。講義・解説・箇条書きの読み上げは不可。

## 実名の好き嫌いと、ネットでの下調べ（2026-10-27 ユーザーの指示）

「現実のアーティストを出して好き嫌いを述べてほしいし、かなりマニアックなアーティストのネタもだしてほしい。オジー・オズボーンの最終ライブに感動したとか、ゼルダの音楽はインタラクティブで緊張感があってもいいとか。ネットで情報を詳しく集めないとオタクっぽい会話はできないよ」

- 実在の作品・人物・会社・プロジェクトを名前で出し、好き嫌いをはっきり言う（「あれは好き」「あの人のあの時期は苦手」）。有名どころだけでなく、詳しい人しか知らない人・作品・事件も出す。
- 書く前に WebSearch / WebFetch で詳しく集める：本人や関係者のインタビュー、ライブの日付・会場・セットリスト、制作の裏話、ファンの間の定番の議論、最近の出来事（2025〜2026年のことも調べる）。集めた材料は src/sources/<id>/ に残す。
- 好き嫌いは意見として言う。実在の人物について、確かめていない悪い噂・私生活の憶測・事実と違う中傷は書かない。

## 最近の話（2026-10-27 ユーザーの指示）

「話題が若干古い気もするので、最近の話も入れてね」「1980からまんべんなく拾ってほしい」。
- バイブルの knowledge と episodes は、1980年代・90年代・2000年代・2010年代・2020年代（2026年まで）の5つの年代に、だいたい同じくらいずつ散らす。どこかの年代に偏ったら、足りない年代を足す。バイブルの episodes には年代の印（例：〔80s〕〔2020s〕）を付ける。
- 一つの回の中でも、主題の年代だけで終わらせず、ほかの年代との比較や「その後」をいくつか混ぜる（チャットの「最近だと〇〇でしょ」、昔と今の比べ）。
- 最近の事実は特に確かめてから使う。

## 人間味（2026-10-27 ユーザーの指示）

「全員、人間味のある発言をさせて。バグらせたとか LLM のせいで仕事がないとか」

- 知識の語りの合間に、本人の生活と失敗を出す：自分でやらかした話（本番でバグらせた、データを飛ばした、締切を落とした、録音を消した）、仕事の不安と愚痴（LLM のせいで案件が減った、単価が下がった、AI に仕事を取られた、上司・客・家族への恨み）、お金・体調・寝不足・人間関係の悩み。専門家なのに生活は不器用、が笑いと親しみになる。
- 愚痴は具体的に（何を、誰に、いくら、何時間）。悲壮にせず、自分で笑い飛ばすか、チャットに慰められて逆ギレする。
- 一つの回で3〜5回は、知識と関係のない生身の話を入れる。
- ネタは毎回ちがうものを、具体的な数字と場面で。例（ユーザーの例を含む）：深夜の障害対応で30時間以上働いた、子どものある時期だけの言い間違いが消えて可愛かったのに残念、寝ている間に旦那にちょっかいを出された、LLM のせいで仕事がない、本番でバグらせた、締切の前夜に録音を消した、健康診断の数字、家賃の更新、実家からの電話、推しの引退、寝落ちして配信を切り忘れた。回をまたいで同じ愚痴を使い回さず、前の回の愚痴の「その後」を語るのは可。

## 濃さ

- 1分（約8〜10行）に一つは、具体的な事実・名前・数字・逸話か、言い切る持論を入れる。薄い相づちや同じ論点の言い換えで尺を埋めない。
- 一つの回で論点を5〜8個立て、それぞれに「体験談 → 事実 → 持論 → オチ」のどれかの転がしを付ける。前半と後半で同じ話をしない。
- 知識は正確に。自信のない年・数字・引用は書かない（ぼかすより削る）。作者がこの回で持ち帰れる知識を3〜5個、意識して入れる。

## 面白さ

- 笑いの型はバイブルの humor。大げさな理屈と小さな生活の落差、自分の理屈が自分に返る、チャットとの言い合いで負ける、など。
- オチは言い切って短く。説明して笑わせない。同じ落ち・同じ口癖を一つの回で繰り返さない。
- チャットは配信を食うくらい強くてよい。配信者が言い負かされる、訂正される、脱線させられる場面を入れる。

## 下ネタ

- サキュバスなので下ネタは可。配信中に1回の回で2〜4回、キャラの領域の言葉とかけて出す（例：ノクスの「いきなり本番」→「本番環境の話よ」）。
- チャットの下ネタには必ず反応する。かわす・言い返す・上を行く・領域の話に引きずり込む、のどれか。照れるかどうかはキャラ次第。
- 露骨な性行為の描写はしない。実在の人物を性的にしない。未成年に見える要素は入れない。視聴者を本気で辱めない。

## 時刻と表情

- 配信はユーザーが画面を開いたときに始まっている扱いで、時計の時刻とは結び付かない。「朝七時」「八時四十五分」のように時刻を言い切らない。朝・昼・夜を感じさせたいなら「起きたばかり」「お昼食べた？」程度にぼかすか、時間帯に依らない入りにする。
- 台詞に表情を付けられる：`- say: {face: smile, text: 台詞}`（smile 笑顔、smug ドヤ、shy 照れ、surprised 驚き、annoyed ジト目）。次の台詞で元の顔に戻る。オチ・言い負かされた所・下ネタへの反応・驚く事実など、10行に1回くらいを目安に付ける。付けすぎない。

## 声（voice/<id>.yaml）

- 子どもの言葉（子ども・娘・息子・保育園など。`- tag: kids`）と、未成年の視聴者の言葉（中学生・高校生・16歳など。`- tag: minor`）への反応は、下ネタより前に置く（子どもや未成年に下ネタの返しが付かないように）。
- `- tag: minor` には `remember: {minor: 1}` を付ける。未成年への返しに、性的な代案や条件つきの誘い（「大人になったら」など）を置かない。
- `safe_refusal:`（1〜3通り）に、未成年と申告した視聴者と子どもが出る回で下ネタに返す断りを、その人の口調で書く（形は src/README.md）。短く断って普通の話に戻す。下ネタの言い換え・匂わせ・照れ芸にしない。各下ネタの反応の cases に同じ条件を手で書かない（tools/import_stream.py が lewd の組の全部に自動で足す）。
- 子どもが出る回は、回の YAML の先頭に `family: true` を書き、台本に性的な冗談を置かない。
- その次に、下ネタへの反応をまとめる。少なくとも次の種類を、それぞれ alts で4通り以上：
  胸・尻・脚、見せて・脱いで、エッチ・やらせて・抱いて、精気・吸って・搾って、下着・パンツ、処女・童貞、結婚・付き合って・彼女に、キス、ムラムラ・興奮、下ネタ全般（えろ・変態）、性器の名前。
- 全員が使う判定（子ども・未成年、下ネタ、年齢・見た目のいじり、荒らし、褒め、要望、メタ、ほかの配信者、挨拶・日常の報告）は src/tags.yaml にある。match を書かず `- tag: kiss` のように名前で使い、返しの alts だけを書く。並びは src/tags.yaml の冒頭のとおり（safe → lewd → tease・troll・praise・request・meta・rival → 得意領域の match → chat）。名前の一覧も src/tags.yaml を見る。判定の漏れや誤反応に気づいたら、自分で直さず報告すること。確かめは `python3 tools/kwtest.py <id>`（未使用の名前も出る）。
- プレイヤーが打ちそうなコメントは src/research/expected-comments.md に分類してある。返しを書くときに読む。
- 返しは毎回うまい返しや落ちで締めない（2026-10-27「型はあってもいいのだが、狭いのだと思う。オチがなくてもいいときがあるはずだ」）。「わかる」「へー」「それな」だけ、流す、聞き返すだけ、の短い返しを各反応に混ぜる。担当分野の名詞（帳面・規則・作法・ログ・日誌・セーブ）を全部の返しに当てはめない。「……」「ふふ」「あはは」を飾りに使わない。
- 雑談の派閥（きのこ・たけのこなど。src/bible/likes/_factions.yaml）への返しは、その人の派閥に合わせ、`remember` で視聴者の派閥を覚え、`cases` の `mem` で寝返り（前と反対の派閥）や次の挨拶で拾う。時間帯（深夜）・初見と常連で変わる挨拶も `cases` で書く（形は src/README.md）。
- 年齢・見た目のいじり（BBA、何歳、太った、角、服）は、その人の person から自然に出る返しにする（怒る・開き直る・年で殴り返す・拗ねる・笑う）。荒らしは短く流すか笑いに変え、本気で言い返さない。「AI？」「中の人」には世界観を壊さずにかわす。
- そのほかの match は日本語と英語の両方の言い方を入れた正規表現にする（例：`おっぱい|胸|乳|boob|tits|breast`）。視聴者は英語でも書く。英訳の voice でも match は日本語版と同じ文字列のまま（変換で確かめる）。
- そのあとに、得意領域の言葉への反応（20個以上）、挨拶・雑談への反応。
- alts の書き方：

```yaml
keywords:
- match: おっぱい|胸|乳|boob|tits|breast
  alts:
  - ['{name}、そこを見る前に画面の文字を読んで。']
  - ['見てるのは知ってるわ。', '……視線にも課金できたらいいのに。']
```

## 英訳（src/en/）

- 英訳は、日本語の回がユーザーに確定されてから書く（日本語を直すと並びがずれるため）。指示があるまで書かない。

- 回：src/en/episodes/<id>/NNN.yaml。日本語と同じ並び（拍の数・種類・話す人・質問の答えと返しの数）。変換が突き合わせる。
- 声：src/en/voice/<id>.yaml。match は日本語版と同じ文字列。
- 訳し方：英語圏の配信者が実際に言う自然な口語にする（直訳しない）。キャラの口調を英語で作る（例：リゼは気だるく皮肉、エラは過剰に丁寧な執事英語、ピムは勢いのある優等生）。ジョークは英語で笑えるように作り直してよいが、事実と論点は変えない。
- 裏テーマは作者の英語学習。覚える価値のある言い回し・スラングを自然に使う。日本の固有名詞は英語圏で通じる名前に（ドラクエ → Dragon Quest）。
- 視聴者の名前（chat の最初の要素）も英語のハンドル名に訳す。

## 作業用のファイル

作業用フォルダ（scratchpad）はほかの書き手と共有している。下書きや一時ファイルは必ず scratchpad/<id>/（例：scratchpad/nox/）の下に置き、ほかのキャラの名前のフォルダには触らない。2026-10-27 に、同じ名前の下書きが上書きされてノクスのバイブルが一時リゼの項目に入れ替わる事故があった。

## 確かめること

- `python3 tools/build.py` が ok。回の長さは data/ja/ep/<id>/<n>.json の secs（2400〜3300秒が目安）。
- 担当外のファイルは編集しない。
