## NES PPU のスプライト評価
- 1本の走査線に出せるスプライトは8枚。見つかった順に最初の8枚を選ぶ。二次 OAM は32バイト → https://www.nesdev.org/wiki/PPU_sprite_evaluation
- 評価は dot 1–64 で二次 OAM を $FF で消し、dot 65–256 で評価、257–320 で8枚ぶんの絵を取りに行く → https://www.nesdev.org/wiki/PPU_sprite_evaluation
- 8枚見つけたあとの9枚目探しで m（バイトの位置）も一緒に増える不具合があり、OAM を「斜めに」読む。タイル番号や属性やXをYとして比べるので、オーバーフローのフラグは誤検出も見逃しもする → https://www.nesdev.org/wiki/PPU_sprite_evaluation
- スプライト同士の優先は OAM のアドレス順（若い番号が手前）→ https://www.nesdev.org/wiki/PPU_OAM
- Y座標は1ライン遅れて出るので、書く前に1引く → https://www.nesdev.org/wiki/PPU_OAM
- Y を $EF〜$FF にすると隠れる → https://www.nesdev.org/wiki/OAM

## オーバーフローのフラグと8枚の制限を使ったゲーム
- Bee 52 はタイトル画面で、オーバーフローのフラグを使って走査線165で画面を分ける → https://www.nesdev.org/wiki/Sprite_overflow_games
- City Trouble はオーバーフローのフラグとスプライト0の両方で、スクロールを2か所で分ける → 同上
- ゼルダの伝説はダンジョンの画面の上か下を隠す。忍者龍剣伝1〜3は、カットシーンのスプライトを黒い枠の内側に収める。悪魔城ドラキュラII（Simon's Quest）は沼に入ったとき下半身を隠す → 同上
- 忍者龍剣伝のそれ以外の隠し方（1作目の落とし穴に落ちるリュウなど）は優先ビットでやっている → https://nesdev.org/wiki/Talk:Sprite_overflow_games
- Solstice のオープニングで余計なスプライトが見えないのは、ハードが落としているだけ（「ハードが失敗を隠している」）→ https://www.nesdev.org/wiki/Sprite_overflow_games
- 8枚の制限を外す設定にすると、ゼルダでリンクが壁の下ではなく上を歩く。同じYで同じタイルのスプライトが8枚並んでいたら、隠しに使っている印 → https://nesdev.org/wiki/Talk:Sprite_overflow_games 、https://tasvideos.org/Forum/Posts/441699
- Mesen2 にはスプライトの上限の設定がある（Normal / Adaptive / Off）→ https://docs.libretro.com/library/mesen2/

## ちらつき
- OAM の場所を固定せず、毎フレーム並べる順を変えて、消える分を散らす。消えっぱなしをちらつきに替える → https://nesdev.org/wiki/Don't_hardcode_OAM_addresses 、https://nesdev.nes.science/f10/t18010.xhtml
- 優先ビットで背景の後ろに回しても、同じ行の他のスプライトの枠は食う → https://nesdev.nes.science/f10/t18010.xhtml

## SMB3 の優先ビットの癖
- 背景の後ろにする不透明なスプライトを若い番号に置くと、それより後の番号の手前スプライトまで隠して背景が見える。SMB3 はこれを、ブロックから出てくるアイテムに使う。1-2 の音符ブロックの角が四角く欠けて見えるのはそのせい → https://www.nesdev.org/wiki/PPU_sprite_priority

## OAM DMA と OAM の記憶
- OAM DMA は 513 CPU サイクル（奇数サイクルなら+1）。LDA/STA を並べると4倍ほどかかる → https://www.nesdev.org/wiki/PPU_OAM
- OAM は描画を止めると少しの間は持つが、そのあと崩れる。NTSC では描画を止めている間はリフレッシュされない → https://www.nesdev.org/wiki/PPU_OAM
- PAL の 2C07 は走査線 265〜310 で OAM を強制的にリフレッシュするので、長い垂直帰線を使うソフトは DMA を帰線の早いうちにやる → https://www.nesdev.org/wiki/PPU_OAM

## スプライト0
- スーパーマリオのスプライト0は、上のステータスバーのコインの下2行を写したもの。NMI でスクロールを0にして、スプライト0のヒットを待ってから本当のスクロールを書く → https://nesdev.nes.science/f3/t12185.xhtml
- 1フレームで拾えるスプライト0のヒットは最初の1回だけ → https://www.nesdev.org/wiki/PPU_OAM
- アダムス・ファミリーは、スプライト0に背景が重なってステータスバーが1ドットずれる → https://www.nesdev.org/wiki/Game_bugs

## 処理落ちとゴミのスプライト
- ストライダー飛竜（NES）は処理落ちのフレームで、作りかけの表示リストを NMI が OAM に送ってしまい、ゴミのスプライトが出る → https://www.nesdev.org/wiki/Game_bugs
- ダブルドラゴンはスプライト0と1が右下にゴミとして出る（タイル $FF と $FE、0番は優先ビット付き）→ https://www.nesdev.org/wiki/Game_bugs

## MMC3 の割り込み
- MMC3 の IRQ は PPU の A12 の立ち上がりで数える。背景を $0000、スプライトを $1000 に分けると、スプライトの絵を取りに行く dot 256–319 で1行に1回 A12 が上がる。分けないと正しく動かない → https://www.nesdev.org/wiki/MMC3
- 0を書いたときの割り込みの出方は、シャープの MMC3B/C と、MMC3A や NEC 製で違う → https://www.nesdev.org/wiki/MMC3

## ゲームボーイ
- 40個まで、1行に10個まで。OAM の順に最初の10個を取る。X が 0 や 168 以上で隠したものも数に入るので、Y で隠す → https://gbdev.io/pandocs/OAM.html
- 重なったとき、初代（DMG）は X が小さい方が手前、カラー（CGB）は OAM の順だけ → https://gbdev.io/pandocs/OAM.html
- 初代では、16ビットのレジスタが $FE00〜$FEFF を指したまま増減すると、モード2の間に OAM が壊れる。カラーとアドバンスでは起きない。0番と1番は壊れない → https://gbdev.io/pandocs/OAM_Corruption_Bug.html

## スーパーファミコン
- 1行に32枚、8×8のタイルで34枚まで。超えると $213E の Range Over / Time Over が立つ。タイルの数え方は逆順 → https://snes.nesdev.org/wiki/OAM 、https://www.sneslab.net/wiki/sprite
- 優先順を回す機能がある（$2102–$2103 のビット15）→ https://www.sneslab.net/wiki/sprite

## 追記（MMC3 と 8×16、空席の取りに行き）
- 8×16 では PPU A12 を明示的に追う必要がある。組み合わせ次第でカウンタが最大4回減る。8×16 で背景とスプライトを両方 $0000 にすると毎行数える → https://www.nesdev.org/wiki/MMC3
- 8×16 でも標準は背景 $0000、スプライト $1000 → 同上
- 1行のスプライトが8枚未満のとき、残りの分はタイル $FF（$1FE0–$1FFF）を取りに行って捨てる → 同上
- PPUCTRL のビット5で 8×16。8×16 ではスプライトの表の選択ビットは無視される → https://www.nesdev.org/wiki/PPU_registers

## 追記（PPU レジスタ・ゲームボーイ・スプライト0）
- 2C02G では OAMADDR に書くと OAM が壊れ、だいたい 8・9番（$20）の8バイトが書いた先の行に写る → https://www.nesdev.org/wiki/PPU_registers
- OAMDATA を描画中に読むと PPU の中の OAM の読み書きが見える。昔は当てにならないと思われていた → 同上
- Super Cars は 2C02G より前の PPU で OAMDATA が読めず、画面の上がちらつく。Topple Zip は 2C02G 以降で描画中に OAMDATA の鏡を読み、空いたバスに頼るのでゴミが出ることがある → https://www.nesdev.org/wiki/Game_bugs
- スプライト0のヒットは X=255 では起きない。PPUMASK でどちらかを切っている所、左8ドットを隠している所でも起きない。ヒットを待って来ないと落ちることが多い。処理落ちのフレームで扱わないゲームがある → https://www.nesdev.org/wiki/PPU_registers
- Battletoads は描画を入れ直したときの遅れがないと落ちる → 同上
- Lunar Limit、Irritating Ship は、スプライト0を本当の当たり判定に使う → 同上
- ゲームボーイのモード3は 172〜289 dot。描く物1つで 6〜11 dot 延び、X=0 は常に 11 dot。その分だけモード0（HBlank）が縮む → https://gbdev.io/pandocs/Rendering.html
