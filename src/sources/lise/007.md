## ゲームボーイ
- 1行に10個、全部で40個。X を 0 や 168 以上にして隠しても10個の数には入るので、Y で隠す → https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md
- 重なったときの優先：Non-CGB モード（初代、およびカラーで昔のソフトを動かすとき）は X が小さい方が手前（同じ X なら OAM の若い方）。CGB モード（カラー用のソフト）は OAM の順だけ → 同上
  - 台詞は「カラー用に作ったソフトだと番号の若い方が手前」「昔のソフトを動かすときは、カラーも初代と同じ決め方」。前の版の「同じゲームでも見え方が変わることがある」は、本体と動作モードを混同していたので外した。voice の同じ返しも直した。
- 初代だけの OAM の破損（16ビットのレジスタが $FE00〜$FEFF を指したまま増減）→ https://gbdev.io/pandocs/OAM_Corruption_Bug.html

## スーパーファミコン
- 1行に32枚、8×8のかけらで34個まで → https://snes.nesdev.org/wiki/OAM 、https://www.sneslab.net/wiki/sprite
- 優先順の始まりを変える機能：$2103（OAMADDH）のビット7を立てると、OAM のアドレスで選んだ物が一番手前になる。アドレスは V-Blank の始めに $2102/$2103 に書いた値から入れ直される → https://wiki.superfamicom.org/sprites 、https://sneslab.net/wiki/Priority_Order_Shifting
  - 毎フレームその値を変えて回すのはプログラムの仕事で、機械が自動で回すわけではない。台詞は「始まりの番号を選べる」「毎回変えるのは作る人の仕事」にした。任天堂の開発マニュアルの写し（https://floating.muncher.se/bot/manual/book1_text.pdf の Priority Order Shifting）も、レジスタに優先の開始番号を設定する説明。
- 絵の位置の表が二つ（512バイトと32バイトの上位の表）→ https://snes.nesdev.org/wiki/OAM

## ファミコンの OAM DMA
- OAM は描画を止めると少しの間で崩れる。DMA は 513 サイクル、LDA/STA を並べると4倍ほど → https://www.nesdev.org/wiki/PPU_OAM
