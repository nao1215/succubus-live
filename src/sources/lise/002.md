## 2013年3月の分岐（BIP50）
- 0.8 は LevelDB、0.7 以前は Berkeley DB。ブロック225,430 を 0.8 の採掘者が作り、0.8 は受け取り、0.7 以前の一部は BDB のロックが足りずに拒んで分岐 → 確 https://github.com/bitcoin/bips/blob/master/bip-0050.mediawiki 、https://bitcoin.org/en/alert/2013-03-11-chain-fork
- ロックの設定が「暗黙のうちにネットワークの合意の規則になっていた」→ 確 BIP50（台詞は「こういう意味の一文」として訳した）
- 必要なロックの数は各ノードの blkindex.dat の並びで違い、同じ 0.7 でも通す・通さないが分かれた → 確 BIP50
- thermoman が IRC で「よそのノードが225,431個あると言う」と書いた → 確 https://bitcoinmagazine.com/technical/bitcoin-network-shaken-by-blockchain-fork-1363144448
- 0.7 の鎖を選んだ理由（両方が読める）。分岐は24ブロック・約6時間、0.8 側は最大13ブロック先 → 確 同上
- BTCGuild と Slush が 0.7 に戻して決着 → 確 BIP50
- 計算力の7割超が少数のプールに集中 → 確 Bitcoin Magazine 同上
- BitPay・Mt.Gox などが入金を停止 → 確 同上
- 211 BTC 超の二重払い（OKPay と本人の別の宛先）→ 要 https://bitcoinmagazine.com/markets/okpay-takes-bitcoin-hiatus-2-1369773165 （本人の掲示板の書き込みの報道。台詞でも「本人が掲示板に書いた話だと」と断った）
- 二重払いは悪意のない試し、プールのノードを再起動したときにメモリプールが消えたのが成功の理由 → 確 BIP50。台詞ではリゼがまず「攻撃だった」と言い、常連に BIP50 で訂正される形にした（リゼの間違いの演出。事実としては「試し」）。
- 0.8.1：二か月、一万ロック超になりそうなブロックを拒み、作るブロックは500,000バイトまで。旧版向けの修正でロックの上限を537,000に。更新できない人には DB_CONFIG で537,000ロックにするやり方を案内（"how to set DB_CONFIG to 537,000 locks"）。2013年8月16日、ブロック252,451で未対応のノードが切り離された → 確 BIP50。DB_CONFIG の具体的な書式（set_lk_max_locks）は確かめていないので台詞に出していない。
- 「六確認」がこの夜は役に立たなかった → Bitcoin Magazine の13ブロック（確）。言い伝えの部分はリゼの意見
- サトシの論文の計算は正直な鎖と攻撃者の競争 → 確 https://bitcoin.org/bitcoin.pdf 第11節（モーラのメモで確認済み）

## ゲームのたとえ
- ポケモン金・銀の増殖：PC に預けてから「ボックスをかえる」を選び、その強制セーブの最中に電源を切ると、手持ちとボックスの両方に残る → 要 https://bulbapedia.bulbagarden.net/wiki/List_of_cloning_glitches 、https://ocf.berkeley.edu/~jdonald/pokemon/gscclone.html 。台詞ではリゼがまず「赤・緑」と言い、常連に「金・銀」と訂正される。切る瞬間の細かいタイミングは資料で幅があるので「セーブの途中で」とだけ言った。
- 2C02G、MMC3 の個体差 → 001 の出典（src/sources/lise/001.md）
- 「書き込みが途中で止まって両方が正しいと言う」はリゼのたとえ（増殖の正確な内部の説明ではない）
