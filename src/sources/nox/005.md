# ノクス 003「同じソフトなのに答えが割れた夜（2013年）と、十一台のうち一台だけ違った私の試験」出典

2026-10-27 夜 新規。もとはリゼの 002（src/old/episodes-v6/lise/002.yaml）。2013年3月の分岐・二重払い・0.8.1・Mt.Gox・割れる鎖と止まる鎖・Ronin の事実は、src/sources/lise/002.md と src/old/sources-v4/mora/001.md の確かめに頼っている（下に要点だけ写した）。今回あらたに当たったものは「新」と付けた。
「確」は本文に当たって確かめたもの、「要」は検索結果・二次資料の要約で確かめたもの。

## 2013年3月の分岐（BIP50）
- 0.8 は LevelDB、0.7 以前は Berkeley DB。ブロック225,430 を 0.8 の採掘者が作り、0.8 は受け取り、0.7 以前の一部は BDB のロックが足りずに拒んだ → 確 https://github.com/bitcoin/bips/blob/master/bip-0050.mediawiki 、https://bitcoin.org/en/alert/2013-03-11-chain-fork
- 「ロックの設定が暗黙のうちにネットワークの合意の規則になっていた」→ 確 BIP50（台詞は「こういう意味の一文」として訳した）
- 必要なロックの数は各ノードの blkindex.dat の並びで違い、同じ 0.7 でも通す・通さないが分かれた → 確 BIP50
- thermoman の IRC の書き込み、sipa の「大きな組み替えでも」→ 確 https://bitcoinmagazine.com/technical/bitcoin-network-shaken-by-blockchain-fork-1363144448
- 0.7 の鎖を選んだ理由（両方が読める）、24ブロック・約6時間、0.8 側は最大13ブロック先 → 確 同上
- BTCGuild と Slush が 0.7 に戻して決着 → 確 BIP50
- 211 BTC 超の二重払い → 要 https://bitcoinmagazine.com/markets/okpay-takes-bitcoin-hiatus-2-1369773165 （本人の掲示板の書き込みの報道。台詞でも「本人が掲示板に書いた話だと」と断った）
- 二重払いは悪意のない試し、プールのノードの再起動でメモリプールが消えたのが成功の理由 → 確 BIP50。台詞ではノクスがまず「攻撃だった」と言い、エラッタ収集家に訂正される形（演出。事実としては「試し」）。
- 0.8.1：二か月、一万ロック超になりそうなブロックを拒み、作るブロックは500,000バイトまで。旧版向けにロックの上限を537,000に。DB_CONFIG で増やすやり方を案内。2013年8月16日、ブロック252,451で未対応のノードが切り離された → 確 BIP50。DB_CONFIG の書式は確かめていないので台詞に出していない。
- 「六確認」がこの夜は役に立たなかった → 13ブロック（確）。言い伝えの部分はノクスの意見。
- Mt.Gox などが入金を停止 → 確 Bitcoin Magazine 同上

## 読み比べ：CVE-2018-17144（新）
- 0.14 の PR 9049 が、2012年（PR 443）からある「一つの取引で同じ入力を二回使っていないか」の確認を、速くするために外した。0.14 では assert で落ちるだけ。0.15 の作り直しで assert が「出力があるか」だけを見るようになり、前のブロックの出力なら、採掘者が量を増やせる形に化けた → 確 https://bitcoincore.org/en/2018/09/20/notice/
- 9月17日 14:57 UTC に匿名の報告、17:47 に Matt Corallo が増やせる方に気づく、9月18日に 0.16.3 → 確 同上
- 0.14 が2017年に出た → 一般知識（モーラのメモで 0.14 は2017年3月）
- 「組み込みでは assert を本番で消すことも多い」「assert は見張りじゃなくてメモ」→ 常連とノクスの意見（NDEBUG の一般的な使い方）
- 手口の手順（どんな取引を作るか）は台詞にしていない。

## 追記（2026-10-27 深夜、シニアの水準への直し。Codex の指摘）
- BIP50（読んだ、2026-10-27）：「A block that had a larger number of total transaction inputs than previously seen was mined and broadcasted.」「the lock usage could vary from node to node」「there was at least one large double spend」→ https://github.com/bitcoin/bips/blob/master/bip-0050.mediawiki 。台詞を「入力がそれまでで一番多い頁」「少なくとも一件」に直した（指摘 32、33）。
- 仕事量（chainwork）は計算の回数ではなく各ブロックの難易度から足す、有効と認める鎖の中で比べる：Bitcoin の一般知識。台詞に足した。
- Ethereum と Ethereum Classic は違う規則を選んだ人たちがそれぞれを動かし続けている。一時的な分岐が再収束する BIP50 とは別、と台詞で分けた（指摘 16）。
- NAS の件：上限を直す前に、開けなかったら結果を出さずに止まるよう試験を直す（指摘 31）。
