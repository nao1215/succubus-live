## Docker と PID 1

- Dockerfile のシェル形式の ENTRYPOINT は /bin/sh -c の子として動き、シェルはシグナルを渡さない。実行ファイルはコンテナの PID 1 にならず、Unix のシグナルを受け取らない。docker stop の SIGTERM も届かず、待ったあと SIGKILL。exec 形式が推奨。シェル形式の CMD も /bin/sh -c で包まれる。（読んだ）
  → https://docs.docker.com/reference/dockerfile/
- docker stop の既定の待ち時間は Linux のコンテナで 10 秒（Windows は 30 秒）。（読んだ）
  → https://docs.docker.com/reference/cli/docker/container/stop/
- PID 名前空間の init には、ハンドラを付けたシグナルしか同じ名前空間の中から送れない（特権があっても）。親の名前空間からも同じで、SIGKILL と SIGSTOP だけは強制で届く。親をなくした子は init に引き取られる。init が終わると中の全部に SIGKILL。（読んだ）
  → https://man7.org/linux/man-pages/man7/pid_namespaces.7.html
- tini：子を一つ起こし、ゾンビを刈り、シグナルを渡す。SIGTERM で正しく止まるようにする。Docker 1.13 以降は --init で同梱の tini。（読んだ）
  → https://github.com/krallin/tini

## Kubernetes

- Pod の終了：主プロセスに TERM、猶予の既定は 30 秒、preStop は猶予の中で走り、超えると一回だけ 2 秒の延長、過ぎたら KILL。サイドカー（restartPolicy: Always の init コンテナ）は最後の主コンテナが止まってから、定義と逆の順に TERM。（読んだ）
  → https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/
- ネイティブのサイドカーは 1.28 で入り、1.33（2025年4月23日）で安定版。（検索。公式の Sidecar Containers の頁の「Stable since v1.33」「first available in v1.28」）
  → https://kubernetes.io/docs/concepts/workloads/pods/sidecar-containers/

## Go

- Go 1.14（2020年2月25日）：ゴルーチンが非同期に横取りされる。Unix では前より多くのシグナルを受け取り、syscall や golang.org/x/sys/unix を使うプログラムは遅いシステムコールが EINTR で失敗することが増える。やり直すループを書け。（読んだ。日付は公式ブログの記事で検索）
  → https://go.dev/doc/go1.14
- 横取りのシグナルが SIGURG である理由（runtime/signal_unix.go の sigPreempt のコメント）：デバッガが既定で素通しする、混ぜた C の libc が内部で使わない、「理由なく届いても何も起きない」、実時間シグナルのない macOS でも使える。（読んだ）
  → https://github.com/golang/go/blob/master/src/runtime/signal_unix.go
- os/signal：Notify はチャンネルへの送信で待たない。受け手が追いつく分のバッファは呼ぶ側の責任、一つの合図なら 1 で足りる。NotifyContext は Go 1.16。（読んだ）
  → https://pkg.go.dev/os/signal
- Go 1.17：go vet がバッファなしのチャンネルを signal.Notify に渡すのを警告。（読んだ）
  → https://go.dev/doc/go1.17

## Unix のシグナルの歴史

- signal(2)：昔の Unix と System V はハンドラが呼ばれると SIG_DFL に戻した（張り直す前に再び届くと危ない）。BSD は戻さず、ハンドラ中は同じシグナルを止めた。POSIX が sigaction で収めた。glibc 2 以降の signal() は BSD の意味で sigaction を呼ぶ。頁の頭に「使うな、sigaction を使え」。（読んだ）
  → https://man7.org/linux/man-pages/man2/signal.2.html
- Gabriel「The Rise of Worse is Better」：MIT の人と Berkeley の（Unix の）人の会話。MIT 側は「巻き戻して、呼んだ命令に PC を戻すのが正しい」、Unix 側は「必ず終わらせ、ときどきエラーを返す。呼ぶ側が確かめてやり直す」。MIT 側は「実装は簡単だがインターフェースが複雑」、Unix 側は「実装の簡単さを選んだ」。（読んだ）
  → https://www.dreamsongs.com/RiseOfWorseIsBetter.html
- 「worse is better」は 1989 年春に冗談で言った言葉、1990 年3月の EuroPAL の基調講演で形に。（読んだ）
  → https://www.dreamsongs.com/WorseIsBetter.html
- self-pipe trick：select の直前に届くシグナルの競合を、パイプの読み口を select で見張り、ハンドラが non-blocking の書き口に一バイト書いて解く。本人は 1990 年ごろと書く。（検索。本文は取得に失敗）
  → https://cr.yp.to/docs/selfpipe.html
- signalfd は Linux 2.6.22（glibc 2.8）、signalfd4 は 2.6.27。2.6.22 は 2007 年。（読んだ。年は既知）
  → https://man7.org/linux/man-pages/man2/signalfd.2.html
- SA_RESTART で多くの遅いシステムコールは再開されるが、再開されないものもある（signal(7) の既知の内容。本文は今回読んでいない）。
  → https://man7.org/linux/man-pages/man7/signal.7.html
- ハンドラの中で使ってよいのは async-signal-safe な関数だけで、printf は含まれない（signal-safety(7) の既知の内容。本文は今回読んでいない）。
  → https://man7.org/linux/man-pages/man7/signal-safety.7.html
